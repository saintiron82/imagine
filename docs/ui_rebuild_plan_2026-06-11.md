## 1. 디자인 브리프

| 항목 | 내용 |
|---|---|
| 주 사용자 | 한 앱을 같이 쓰는 두 역할 — **일반 사용자**(디자이너: 검색이 전부, 가끔 자기 분석기 제공)와 **운영자**(폴더 등록, 처리 시작, 클러스터 관제, 멤버 관리) |
| 30초 이해 목표 | "**넣고 → 기다리고 → 찾는다**"가 한 지도 위에 있다. 추가하면 어디서 진행을 보고 언제부터 검색되는지 묻지 않아도 안다 |
| 단일 핵심 액션 | 일반 사용자: **검색**. 운영자: **+ 추가** (전역 주 액션) |
| 보여야 하는 상태 | 처리 진행(잡/phase), 분석기 상태, 파일별 "분석 대기"(점진 가용성), 실패와 사유 |
| 피해야 할 느낌 | 관리 도구의 미로 — 같은 일이 세 탭에 흩어지고, 같은 스위치가 세 곳에 있는 현재 상태 |

## 2. 진단 (현 UI가 어려운 이유)

1. **의도가 아니라 파이프라인 단계로 조직됨**: "폴더를 검색 가능하게"라는 한 가지 일이 아카이빙(등록)→분석(진행)→검색(결과) 세 탭에 분산. 잡 시작 진입점만 3개(트리 우클릭/헤더 버튼/FolderInfoBar).
2. **설정 스코프 혼재**: 나(언어·밀도)/이 컴퓨터(AI tier·분석기 시간표)/서버(자동 처리·도메인·DB 도구)가 5군데(설정·워커 탭·관제 패널·사이드바·헤더 DB메뉴)에 섞임. 자동 처리 토글은 3곳에 중복.
3. **역할 평탄화**: 매일 쓰는 검색과 연 몇 회 쓰는 관리자 도구가 같은 탭 줄에 평등하게 나열.

## 3. 새 정보 구조 (IA)

```text
┌────────────────────────────────────────────────────────────┐
│ Imagine   [검색] [라이브러리]      [+ 추가]   [관리] [설정] ⚙ │
└────────────────────────────────────────────────────────────┘
검색        전원 · 기본 탭 · 현 SearchPanel 이식 (해자 — 재작성 금지)
라이브러리   운영자 · 구 아카이빙+분석 통합: 폴더 트리(커버리지) + 처리 현황(잡 카드)
+ 추가      운영자 · 전역 주 액션: 소스 선택→옵션→시작 단일 플로우 (드래그&드롭 동일)
관리        운영자 · 분석기 관제 / 멤버 / 서버 도구(DB·감사·연결·피드백)
설정        전원 · 3스코프: 나 / 이 컴퓨터 / 서버(운영자만 노출)
```

역할별 가시성: 일반 사용자 = 검색 + 설정(나/이 컴퓨터). 운영자 = 전부.
"이 컴퓨터" 섹션에 분석기 제공(시간표·벤치마크)이 들어가므로, 일반 사용자도
자기 머신 기여는 설정에서 켠다 — 별도 "워커 탭" 개념 소멸.

### 설정 항목 이동표 (스코프별 단일 위치 원칙)

| 항목 | 현재 위치 | 새 위치 |
|---|---|---|
| 언어, 그리드 밀도 | 설정+헤더 | 설정 > 나 |
| AI tier, 분석기 시간표/휴식/idle, 벤치마크 | 설정+워커 탭 | 설정 > 이 컴퓨터 |
| 자동 처리(3곳 중복), 배치/휴식 정책 | 설정/워커/관제 | **관리 > 분석기 관제 한 곳** |
| 폴더/NAS 소스 | 아카이빙 사이드바 | 라이브러리 (소스 = 라이브러리의 구성요소) |
| 도메인, DB 도구(내보내기/감사/초기화), 연결 | 모달/헤더 DB메뉴/관리자 탭 | 관리 > 서버 도구 |
| 멤버 | 관리자 탭 | 관리 > 멤버 |

## 4. 핵심 플로우: + 추가

```text
[+ 추가] 클릭 (또는 폴더 드래그&드롭)
 1) 소스 종류: 로컬 / NAS / 기존 소스 다시 분석
 1b) NAS 지정 (NAS 선택 시): 등록된 NAS 목록 → [탐색]
     + 새 NAS 연결 폼 (주소·계정·비밀번호 → 연결 테스트 → 공유 폴더 발견)
 2) 폴더 탐색기 — 2분할:
     좌: 폴더 구조 트리 (계층 내비게이션)
     우: 선택 폴더의 내부 폴더 미리보기 그리드 + 브레드크럼
     하단 선택 바에서 [분석 시작] (2클릭 완주 유지)
 3) 세부(선택): 프로파일(폴더명 추천) / 범위(새 파일만·전체·파도) / 우선 처리
 4) 시작됨: "파싱되는 대로 검색에 나타납니다" → [라이브러리에서 보기]
```

**확정 결정 (2026-06-11): 폴더 선택은 시각 탐색 — 경로 타이핑 금지.**
2단계 탐색기 요구사항:
- 브레드크럼 내비게이션, 폴더 = 카드 (텍스트 입력 필드 없음)
- **폴더 미리보기**: 서버가 썸네일을 가진 폴더(분석 이력 있음)는 2×2 썸네일
  모자이크로 내용을 보여준다 — **NAS 폴더도 동일** ("이미 썸네일이 있다면").
  데이터 소스: files.thumbnail_url을 storage_root 프리픽스로 집계 (신규 API 1개)
- 미분석 폴더는 파일 수 + "미분석" 태그, 부분 분석은 "분석 N%" + 부분 모자이크
- 선택 바: 이름 자동 유도, 하위 포함/자동 분석 인라인 — 같은 화면에서 시작

점진 검색 가용성(파싱 직후 FTS/VV 검색 가능 + "분석 대기" 배지 — 구현 완료)이
3단계의 약속을 사실로 만든다. 추가 직후 검색해도 결과가 나오기 시작한다.

## 5. 구현 계획 (셸 교체 + 장기 이식)

**확정 결정 (2026-06-11): 폴더 지정형.** 분석의 작업 단위는 폴더다 — 파일
단위 처리 진입점(아카이빙의 파일 선택→처리, registerPaths 경로)은 재설계에서
**보존하지 않고 제거**한다. 이미지 하나하나 보면서 일하는 흐름은 운영 모델이
아니다. FileGrid의 파일 선택은 메타데이터 편집·유사 검색 용도로만 남는다.

| 단계 | 내용 | 비고 |
|---|---|---|
| U0 | **선행 제품 결정 2개**: 모드 삼분법 축소(server/client/web → 서버앱/접속앱), 인증 트랙(users vs members) 단일화 | 셸 분기 수를 결정 |
| U1 | 새 셸: 라우터, 데이터 계층(TanStack Query — 폴링 4개+ → 공유 캐시 1개), App.jsx 해체(usePipeline/useServerLifecycle 훅) | 갈아엎기 본체 |
| U2 | 라이브러리 탭 신규(트리+커버리지+잡 카드 통합) + "+ 추가" 플로우 | 백지 정당 — 백엔드 API는 전부 준비됨 |
| U3 | 관리 구역 신규: 분석기 관제(어휘 통일: 워커→분석기, 정지/차단 의미 구분, 차단 목록), 서버 도구 통합 | |
| U4 | 검색면 **이식**(SearchPanel/FileGrid 거의 그대로) + 설정 3스코프 재배열 | 재작성 금지 |
| U5 | 구 표면 제거(아카이빙/분석 탭, 헤더 DB메뉴, 떠돌이 토글, **파일 단위 처리 경로**) + i18n 정리 | 죽은 코드 청소 |

검증: 단계마다 프런트 빌드 + 핵심 플로우 스모크(검색, +추가→잡 생성, 관제 명령).
U1 전에 현행 핵심 플로우의 Playwright 스모크 2~3개를 깔아 회귀 안전망 확보 권장.
