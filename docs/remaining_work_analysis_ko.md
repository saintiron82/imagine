# Imagine — 향후 로드맵 및 남은 작업 분석 리포트

작성일: 2026-02-26  
대상 문서: `phase.md`, `docs/future_roadmap.md`

`phase.md`의 기능 마일스톤과 `future_roadmap.md`의 아키텍처 비전을 종합하여 구체적인 향후 작업 방향을 설계 관점과 비즈니스 가치 관점에서 3가지 핵심 트랙으로 분석했습니다.

---

## 트랙 1: 사용자 경험(UX) 및 앱 완성도 고도화 (Phase 5, 6 UI/UX 트랙)

현재 Phase 4까지 "Triaxis 검색을 통한 이미지 탐색"의 핵심 엔진이 완성되었습니다. 남은 최우선 순위는 이 강력한 엔진을 지렛대로 삼아 상용 제품 수준의 디지털 자산 관리(DAM) 경험을 제공하는 것입니다.

*   **전문적인 탐색 도구 추가:** 라이트박스 뷰어(확대/축소/패닝), 검색 내역, 다양한 정렬 옵션(유사도, 날짜, 평점 기반), 키보드 단축키 등 전문 사용자를 위한 속도감 있는 조작계 구현.
*   **고급 분류 체계 (Collections & Tags):** 이미지 컬렉션(북마크), 스마트 필터 모음, 여러 파일의 태그를 한 번에 묶어서 수정하는 일괄 편집 기능, 그리고 시각적으로 카테고리를 직관화하는 태그 클라우드 도입.
*   **핵심 의의:** "강력한 검색"을 넘어, "찾은 자료를 어떻게 효율적으로 분류하고 재활용할 것인가"를 사용자에게 제공하는 프로덕트의 뷰티 파트입니다.

## 트랙 2: 병목 현상 해소 및 인프라 파이프라인 최적화 (Phase 7, Roadmap 2 & 5)

서버 워커(Phase 4.5~4.8)가 고도화되며 VLM 추론 단계는 향상되었지만, DB 쓰기 동기화 문제가 병목으로 제기되고 있습니다 (`future_roadmap.md` 진단). 따라서 하드웨어를 한계까지 활용하는 파이프라인 튜닝이 필수적입니다.

*   **DB Writer 분리 및 일괄 처리 (P0~P1):** 분석 파이프라인(Inference) 단계와 DB 기록(Write) 단계를 비동기로 분리. SQLite WAL 모드의 장점을 살려 건당 쓰기가 아닌 Batch 단위(500-1000) Bulk Transaction으로 개선.
*   **I/O 및 파싱 최적화:** Pillow 기반 해독을 가속하기 위해 TurboJPEG 등 고속 이미지 디코더 도입 및 멀티프로세스 병렬 파싱(Phase 7) 구현. 증분 인덱싱(Incremental Indexing) 도입으로 기존에 분석한 파일은 빠르게 넘기기.
*   **리소스 절약:** 필요할 때만 모델을 VRAM에 적재하고 안 쓸 땐 비우는 Auto-unload 체제, WebP를 썸네일에 도입해 디스크와 네트워크 대역폭 아끼기 등의 효율화가 포함됩니다.

## 트랙 3: 신뢰성 확보 및 엔터프라이즈 아키텍처 (Roadmap 1, 3, 4, Phase 8, 9)

개인용/팀용 툴에서 나아가 더 견고하고 데이터 검증이 가능한 엔터프라이즈급 생태계로 성장하기 위한 설계 변경과 배포 시스템입니다.

*   **품질 보증 시스템 (Search Quality Eval):** 검색 결과의 연관성(nDCG@10, Recall)을 수치로 파악하여 업데이트가 검색 품질을 떨어뜨리지 않도록 방어하는 오프라인 벤치마크 및 A/B 테스트 체계 구축. (특히 프롬프트나 가중치 RRF 변경 시 필수)
*   **증거 기반 모델링 (Evidence-Centric Model, ECM):** 파일을 덮어쓰는(Last-write-wins) 구조에서 벗어나 상태 이력을 관리. "이 태그나 벡터가 생성된 이유와 확신도"를 남겨 Reranking 알고리즘에 가중치를 부여하도록 자료 구조 개편.
*   **데이터 자산 보존 (Phase 9):** 자동 스케줄 백업 플랜, DB 수동 스냅샷, 깨진 파일 Relink 기능 등을 지원하여 하드웨어 장애로부터 데이터베이스를 보호하고, 외부 내보내기로 타 시스템과 연동 기회를 엽니다.
*   **완벽한 배포 패키지 (Phase 8):** Python 내장 런타임을 포함하여, 어떠한 사전 설치 없이도 실행 가능한 Windows NSIS 기반 앱 배포 및 Portable USB 모드 지원.

### 🚀 다음 작업 제안 (Next Steps)

현재 Phase 4.8과 배포 페이지(Phase 4.9)가 갓 도입된 상황이므로 가장 가성비 높고 체감이 빠른 영역은 두 가지입니다.

1.  **Frontend 체감 영역:** `Phase 5`의 **라이트박스 상세 뷰어** 결합이나 **드래그 앤 드롭 파일 일괄 등록** 기능, 단축키 처리.
2.  **Backend 체감 영역:** `Phase 7` / `Roadmap 2`의 **비동기 DB Writer + SQLite Batch Commit** 체제 전환을 통한 인제스트(Ingest) 파이프라인 속도 정상화(병목 파훼).

어떤 방향부터 먼저 착수할지 결정해 주시면, 세부 설계(Implementation Plan) 구상을 시작하겠습니다.
